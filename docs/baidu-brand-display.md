# 百度搜索结果「来源行」品牌展现说明

本文档回答一个问题：**为什么 `www.58.tl` 的搜索结果条目来源行显示 `www.58.tl`（域名），
而对照站点显示的是「头像 + 中文站名」？我们能不能也显示中文名？**

结论先说：**能显示中文名的那个位置是百度的付费权益「品牌展现」，仅对 VIP 站点开放，
普通站点后台没有提交入口。页面侧的任何改动（标题、meta、结构化数据）都无法改变
「来源行显示域名」这一事实。**

因此本次不做「改来源行」，只做三件可落地的事：

1. 把主站的品牌信号补齐并统一（标题、`og:site_name`、`application-name`、
   `Organization` / `WebSite` 结构化数据全部指向同一个品牌名）；
2. 把「资质与权限」的取证口径沉淀成本文档，避免反复猜测；
3. 记录唯一官方替代路径（关联智能小程序 + MAU 门槛）的投入产出，供后续决策。

> 适用范围：仅主站 `www.58.tl`。子域（mall / block / bct / nft / v / bid / club / model / task）
> 的展示策略另议。文档时点：2026-11。

---

## 一、那个位置到底是什么

百度移动端与 PC 端结果条目里，「标题上方/下方」的 `www.58.tl` 属于**来源行（站点信息行）**，
它的取值来源是百度侧的站点档案，不是页面 HTML：

| 展示形态 | 触发条件 | 数据来源 |
|----------|----------|----------|
| `www.58.tl`（纯域名） | 未获得品牌展现权益时的默认形态 | 百度站点库里的域名 |
| 头像 + `58区块城市`（中文名） | 已获得「品牌展现」权益且审核通过 | 站长在搜索资源平台提交的名称与头像 |

也就是说，**未获得该权益时，来源行只能是域名**。这是平台规则，不是抓取问题，
也不受 `og:site_name`、`<title>`、JSON-LD 影响 —— 这些标签影响的是「标题行」和
「摘要」，以及大模型摘要对站点的实体归因，**不影响来源行**。

## 二、官方规则要点（记录时点 2026-11，以平台实时提示为准）

| 项目 | 规则要点 |
|------|----------|
| 权益归属 | 「品牌展现」（头像 + 站点名称）为 **VIP 站点专属权益**，普通站点无法提交 |
| 审核时长 | 提交后一般 **约 3 个工作日** 出结果，结果在消息中心通知 |
| 修改频率 | 名称通过后 **30 天内只能修改一次**，不要用试错法反复提交 |
| 名称命名 | 必须与站点实际品牌一致；**禁止使用第三方品牌词**、宽泛词（如「城市」「商城」单独成词）、纯域名 |
| 头像要求 | **200×200**，清晰、主体居中；**图内只能包含站点名称文字**，不得含二维码、联系方式、促销语、其他水印 |
| 生效方式 | 通过后逐步覆盖全站结果条目，非即时生效 |

### 命名风险（本次决策的关键）

品牌名沿用「**58区块城市**」——用户认知最强。但名称含「58」，在审核环节存在
**被判定为第三方品牌词**的风险（58 同城为他人商标）。当前处理方式：

- 代码里**不做**任何规避性改写（不改名、不加空格、不加符号），保持品牌一致性；
- 是否调整命名，等第四节「资质核实」有结论后再定，避免为审核反复折腾站点品牌。

---

## 三、当前权限状态（核实结论）

| 核实项 | 状态 | 判断依据 |
|--------|------|----------|
| 站点属性里是否有「品牌展现」入口 | **无** | 该入口仅对 VIP 站点显示，当前站点属性页内没有该项 |
| 是否已购买 VIP | **否** | 拿不到 VIP 资格 |
| ICP 备案主体 | **不明（待核实）** | 仓库内页脚未写入备案号，代码中无备案主体信息 |
| 「58区块城市」商标权属 | **不明（待核实）** | 无商标注册证/授权材料留存 |

> 结论：**在当前权限下，「来源行显示中文名」这条路走不通**，任何页面侧改动都不改变该事实。
> 「ICP 主体」与「商标」两项未核实前，不要提交品牌展现申请，也不要在页脚写入占位备案号 ——
> 虚假备案号是明确违规项。

在提交任何申请之前，先把下面几项查清，结果回填本表：

- [ ] ICP 备案主体名称是谁（个人 / 企业 / 与「58区块城市」品牌的关系）
- [ ] 备案主体是否持有「58区块城市」或「区块城市」相关商标（第 9/35/42 类）

## 五、与「站点 Logo」是两个不同权益

常见误解是把两者当成一件事，实际是两个位置、两套规格、两套审核：

| 维度 | 品牌展现（本文档） | 站点 Logo（见 `docs/baidu-site-logo-guide.md`） |
|------|--------------------|-----------------------------------------------|
| 展示位置 | 结果条目的**来源行**（头像 + 名称） | 标题**左侧**的品牌标识 |
| 展示内容 | 头像 + 中文站点名称 | 一张 LOGO 图 |
| 素材规格 | 头像 **200×200**，图内只能含站点名 | **121×75** / **200×133** |
| 开放对象 | **仅 VIP 站点** | 已验证的普通站点通常可提交 |
| 权限门槛 | 高（付费权益） | 低（站点验证通过即可） |
| 本次动作 | 记录规则与资质清单，**不提交** | 素材已生成，按清单提交 |

> 因此「有中文名效果更好吗」的答案是：**效果确实更好（来源行可识别、点击率更高），
> 但当前拿不到**。现阶段投入产出比最高的替代动作是把**站点 Logo** 提交通过，
> 并让标题行的品牌表述统一（本次已改）。

## 六、唯一官方替代路径：关联智能小程序

若后续仍要拿到「头像 + 名称」形态，公开路径是**站点关联智能小程序**，
并在满足活跃度门槛后申请权益。要点与风险：

| 项目 | 内容 |
|------|------|
| 门槛 | 需先在搜索资源平台完成小程序关联，且小程序 **MAU ≥ 1000** |
| 成本 | 需实际开发并运营一个小程序（评审、上线、持续活跃），不是配置项 |
| 时间 | 达标 + 审核，周期以月计 |
| 风险 | 门槛与权益口径由平台调整，**提交前必须重新确认官方最新规则**；历史上该路径的权益范围也发生过变化 |
| 结论 | 投入远大于「站点 Logo + 品牌信号统一」，**不建议为来源行单独启动**；若本身已有小程序规划，可作为附带收益一并申请 |

## 七、本次已落地的代码改动

目的不是改来源行（改不了），而是让**标题行 / 摘要 / 结构化数据里的品牌指向唯一且一致**，
提升品牌词命中与生成式引擎的实体归因准确度。

| 文件 | 改动 |
|------|------|
| `shared/organization.php` | 新增 `BRAND_NAME`、`BRAND_ALT_NAMES` 常量作为品牌单一来源；`organization_json_ld()` 的 `name` / `alternateName` 改为引用常量（取值不变） |
| `index.php` | `<head>` 前引入 `shared/organization.php` 以取用常量；`<title>`、`og:title` 改用 `BRAND_NAME`；新增 `<meta property="og:site_name">` 与 `<meta name="application-name">`；`WebSite` 结构化数据的 `name` 改用 `BRAND_NAME` |

改动后三处品牌取值必然一致：

```
<title>58区块城市 - 元宇宙同城生活服务平台 | 58 BlockCity</title>
<meta property="og:site_name"     content="58区块城市">
<meta name="application-name"     content="58区块城市">
JSON-LD Organization.name = "58区块城市"
JSON-LD WebSite.name      = "58区块城市"
```

零新增数据库查询、零新增外部请求；只影响 `<head>` 输出。

### 已知遗留（本次不改，仅记录）

- `shared/header.php` 内子站的 `WebSite.name` 取的是页面标题而非品牌常量，
  子站页面的 `WebSite.name` 可能与 `Organization.name` 不一致。范围外，另行处理。
- 页脚 ICP 备案号：**仅在核实出真实备案号后才追加**，本次不写占位内容。
