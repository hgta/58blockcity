# Delta Spec: auction-contract-communication

## ADDED Requirements

### Requirement: 契约联系方式互见

契约成立（落槌且进入契约流程）后，契约页 MUST 向买卖双方展示对方的联系方式（电话/微信，若已填写），MUST NOT 在落槌前展示，MUST NOT 向非契约当事人暴露。

#### Scenario: 双方均已填写时互见

- **WHEN** 契约成立且双方均已填写联系方式
- **THEN** 卖家视角显示买家的电话与微信，买家视角显示卖家的电话与微信
- **AND** 各自的联系方式卡片提供复制按钮

#### Scenario: 对方未填写

- **WHEN** 对方未填写联系方式
- **THEN** 展示「对方未留联系方式」提示，私信联系按钮仍然可用

#### Scenario: 落槌前不可见

- **WHEN** 拍卖尚未落槌
- **THEN** 任何页面不展示契约联系方式（含自己的）

### Requirement: 联系方式自主维护

契约当事人 MUST 能在契约页 inline 填写/修改自己的联系方式（电话、微信，均可空），服务端 MUST 以会话身份判定角色，不接受前端传入角色；手机号 MUST 校验格式（仅数字/`+`/`-`/空格，5–20 位），微信仅限长度与可见字符。

#### Scenario: 卖家补充联系方式

- **WHEN** 卖家在契约页提交自己的电话与微信
- **THEN** 保存成功且买家下次打开契约页可见

#### Scenario: 手机号格式校验

- **WHEN** 提交的电话包含字母
- **THEN** 拒绝保存并提示格式不正确；微信字段不受此限制

#### Scenario: 非当事人不可写

- **WHEN** 非契约当事人提交联系方式更新
- **THEN** 服务端拒绝

### Requirement: 私信直连与文案修复

契约页的联系按钮 MUST 按视角显示「联系买家」（卖家视角）/「联系卖家」（买家视角），链接 MUST 指向站内私信会话 `/messages/?with=<对方ID>`；对方联系方式未填写时该按钮 MUST 仍可用。

#### Scenario: 卖家点击联系买家

- **WHEN** 卖家在契约页点击联系按钮
- **THEN** 按钮文案为「联系买家」并跳转到与买家的私信会话

#### Scenario: 买家点击联系卖家

- **WHEN** 买家在契约页点击联系按钮
- **THEN** 按钮文案为「联系卖家」并跳转到与卖家的私信会话

### Requirement: 卖家侧空值强引导

契约成立后，若卖家未填写联系方式，契约页 MUST 向卖家展示填写引导；人民币契约下 MUST 强调「买家需要你的收款方式才能付款」。

#### Scenario: 卖家未填写时的引导

- **WHEN** 卖家打开自己未填写联系方式的契约页
- **THEN** 显示编辑表单与填写引导提示，引导文案按结算币种区分
