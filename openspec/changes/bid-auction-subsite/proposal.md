# 提案：新增 58拍卖子站（bid.58.tl）

## 背景

当前项目是 PHP 单体多子站架构，已有 block（区块交易）、nft（NFT头像）、mall（商城）、bct（人气值交易）、hufang（互访圈）等子站，共用同一数据库、认证体系、类库和共享组件。

现需新增「58拍卖」子站，用于**拍卖区块**和**拍卖 NFT 头像**，与 `block.58.tl`、`nft.58.tl` 联动（拍卖成交后转移对应物品的所有权）。

## 域名

**`bid.58.tl`** —— 短、语义清晰（bid=拍卖的国际通用词），与现有 block/nft/bct/mall 短英文风格一致。

## 目标

1. 新增 `bid/` 子站目录，复用共用基础设施（数据库、认证、共享头部、Block/NFT/SeoHelper 类）。
2. 支持发布拍卖：拍卖品可为「区块」或「NFT 头像」，设置起拍价、底价（可选）、加价幅度、起止时间、货币类型、可接受支付的城市人气值。
3. 支持登录用户出价，实时更新当前价。
4. 到期自动结算：价高者得，自动转移所有权（区块 / NFT）。
5. 「我的拍卖」：我发布的、我出价的。

## 关键决策（已与用户确认）

| # | 决策项 | 结论 |
|---|--------|------|
| 1 | 拍卖与一口价挂牌关系 | **互斥**：一个物品同一时刻只能有一个一口价挂牌或一个拍卖 |
| 2 | 结算方式 | **系统自动判定**：到截止时间自动成交，价高者得 |
| 3 | 保证金 | **第一版不做**，保持简单 |
| 4 | 支付货币 | 与现有挂牌一致，**人民币 / 人气值两种都支持**；拍卖者可设置接受哪些城市的人气值支付 |
| 5 | 出价门槛 | **必须登录**才能出价 |

## 非目标（第一版不做）

- 保证金 / 信用分机制
- 英式/荷兰式等复杂拍卖规则（仅做英式增价拍卖）
- 实时 WebSocket 推送（用轮询/页面刷新 + 惰性结算）
- 独立 cron 结算服务（用惰性结算替代）

## 受影响文件

### 新建
- `bid/` 子站目录（入口 + includes + auth 代理 + 页面）
- `classes/Auction.php` — 拍卖业务类
- `init/migrate-auction.sql` — 两张新表

### 联动修改（互斥校验 + 成交回调）
- `classes/Block.php` / `classes/BlockListing.php` — 挂牌时校验是否已有 active 拍卖
- `classes/NFT.php` — 出售时校验是否已有 active 拍卖

### 共享
- `config/seo.php` — subdomains 增加 bid
- `shared/admin/admin-menu-config.php` — 后台菜单（可选，后续）
