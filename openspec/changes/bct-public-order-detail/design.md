# Design: bct-public-order-detail

## 背景与现状

```
首页 bct/index.php
 ├─ 买入/卖出挂单条目 ──▶ city.php?city=xx      ← 跳的是城市行情，不是"这张单"
 └─ 「更多」──▶ orders.php?type=buy/sell

已有能力
 ├─ user/order_detail.php          登录 + 本人/交易对手 才能看（私有详情）
 ├─ api/trade_flow.php?action=preview   返回单据字段 + can_claim/in_trade/is_party
 └─ orders.php 行内「接单」→ 弹窗确认（modal UI 已成型）

❌ 空缺：公开的、可分享的单张挂单详情页
```

**D1 · 页面定位**

挂单详情页是**公开资源**，性质接近房源页：任何人可看、可分享，登录后才能操作。因此它 MUST 放在 `bct/` 根目录（不在 `user/` 下），且 MUST NOT 引用 `user/order_detail.php` 会查询的 `email / phone` 等私有字段。

**D2 · 路由**

- 路径：`bct/order.php?id=N`，用主键 id（简单、可读、无需额外查询）；不用 `order_no` 做路由（避免暴露单号生成规则，且多一次查询）
- `id` 非法或订单不存在 → 友好提示 + 跳 `orders.php`，不 404
- 订单处于终态（completed / canceled / expired）时**照样渲染**，状态区显示对应徽标与说明（分享出去的链接不能变死链）

**D3 · 页面结构**

```
┌───────────────────────────────────────────────────────┐
│  挂单详情  #1A2B3C4D              [ 状态徽标 ]         │
├───────────────────────────────────────────────────────┤
│   求购 · 北京BCT                       ← 方向 + 城市    │
│   ¥0.18 / BCT   × 50,000    =   ¥9,000.00             │
├───────────────────────────────────────────────────────┤
│   交易方式   直接交易                                  │
│   剩余有效期 5天13小时                                 │
│   发布时间   10-08 15:31                               │
│   挂单人     用户昵称 💬        ← 私信是小图标链接       │
│   联系方式   ********（按 D6 规则）                     │
├───────────────────────────────────────────────────────┤
│        [ 接单（买入） ]          ← 唯一主 CTA           │
├───────────────────────────────────────────────────────┤
│   交易说明：接单后进入交易中，线下转账后双方在         │
│   个人中心确认（文案与大厅保持一致）                    │
└───────────────────────────────────────────────────────┘
```

**D4 · 角色矩阵（按钮渲染的唯一依据）**

沿用 `orders.php` 现有判定，服务端算完再渲染，前端不做权限判断：

```php
$isMine   = 登录 && o.user_id == me;              // 挂单人本人
$inTrade  = !empty(o.claim_status);               // 有活跃 claim
$isParty  = $inTrade && me ∈ {claim.buyer, claim.seller};
$canClaim = 登录 && !isMine && !inTrade && trade_type==='direct' && status==='pending';
```

| 观看者 | direct · pending | direct · 交易中 | platform / mediator | 终态 |
|---|---|---|---|---|
| 游客 | 「登录后接单」→ login 带回跳 | 灰字「交易中」 | 文案说明，无按钮 | 状态徽标「已结束」 |
| 登录·非参与方 | **「接单（买入）」/「接单（卖给TA）」** | 灰字「交易中」 | 「由平台撮合」/「由中介协调」 | 「已结束」 |
| 挂单人本人 | 「管理我的挂单」→ `user/orders.php` | 「交易中 · 去处理」 | 同上 + 管理入口 | 「查看成交记录」 |
| 交易对手方 | — | 「继续交易」→ `dashboard.php#claims` | — | 「查看成交记录」 |

**按钮原则**：① 主 CTA 唯一（一个 primary 按钮，其余降级为链接或灰字）；② 文案随单据方向走——求购单显示「接单（卖给TA）」，挂售单显示「接单（买入）」，不退化成含糊的「接单」；③ 危险动作（放弃/取消）用 `btn-danger` + 二次确认，并说明后果。

**D5 · 接单交互流程**

```
click 接单
  └─▶ GET preview（服务端再校验一次可接单）
        ├─ can_claim = false → 页面顶部黄条「该单已被接走/状态已变化」+ 自动刷新
        └─ can_claim = true  → 弹确认框（单号/方向/城市/数量/单价/总价/挂单人）
                             → 确认：按钮 disable + loading，POST claim
                                 ├─ 成功 → 跳 user/dashboard.php#claims
                                 └─ 失败 → 框内红字 + 按钮恢复
```

相比大厅现状（抢单失败只 `alert`）的改进：详情页有空间做「顶部提示 + 自刷新」，且确认按钮提交后 MUST disable 防重复提交。

**D6 · 隐私规则（与大厅逐条对齐）**

| 场景 | 展示 |
|---|---|
| 未登录 | 联系方式隐藏，显示「登录后可见」 |
| 登录、未交易 | 显示挂单人登记的 `contact_info` |
| 交易中、非参与方 | 隐藏，显示「交易中 · 暂不可见」 |
| 交易中、参与方 | 显示，附「双方可见 · 私信沟通转账」 |
| `contact_info` 为空 | 「未填写 · 站内信联系」 |

「私信」入口收为**挂单人名字旁的小图标链接**（主 CTA 旁不放大按钮，避免分散注意力）。

**D7 · 状态与失效态文案**

| 订单状态 | 状态区 | CTA 区 |
|---|---|---|
| pending | 待成交 | 按 D4 |
| processing（有活跃 claim） | 交易中 | 按 D4 |
| completed | 已完成 | 「查看成交记录」 |
| canceled | 已取消 | 无 |
| expired | 已过期 + 说明 | 无（引导去大厅看其他单） |

**D8 · 安全**

- 页面公开，MUST NOT 输出 `email / phone` 等私有字段
- 所有动作走 `trade_flow.php`（已含登录断言 + CSRF + 当事人校验），不在页面层自建写操作
- `id` 做 `(int)` 强转；不存在时友好跳转

**D9 · 一期 / 二期边界**

- **一期（本次）**：详情页只做**入口型按钮**——接单在页内完成（modal），交易中的推进动作（确认付款/收款/放弃）跳转个人中心。改动小、风险低。
- **二期（待评估）**：若数据显示用户常在详情页反复查看交易状态，再把 `buyer_confirm / seller_confirm / abandon` 内嵌进详情页，实现"交易全流程不出页"（接口已支持，纯前端编排）。

**D10 · SEO**

暂不做结构化数据（挂单是有时效的报价，收录价值低且易失效）；页面 MUST 输出 `<title>` 与 `description`（城市 + 方向 + 价格），`robots` 沿用站点策略。
