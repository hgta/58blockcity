# Proposal: bct-public-order-detail

## Why

BCT 市场里「一张挂单」没有自己的页面：首页「买入挂单 / 卖出挂单」列表的每一行点击后跳到 `city.php?city=xx`（城市行情页），用户看到的是该城市的行情而不是自己点的那张单；挂单大厅 `orders.php` 只有行内「接单」按钮，没有可展开、可分享的单据视图。

对比站内其它子站——拍卖（`bid/view.php`）、商城（`mall/product/detail.php`）、NFT（`nft/view.php`）都有公开详情页——BCT 挂单是唯一缺失的。这带来三个具体问题：

1. **无法分享**：想让朋友看"这张单划不划算"，只能截图或口头描述；
2. **信息折叠**：城市行情页塞满了走势/盘口/成交，一张单的关键信息（总价、交易方式、剩余有效期、挂单人）反而被稀释；
3. **入口错位**：用户点的是"这一单"，落地却是"整个城市"，认知断层。

数据层其实已经完备：`bct/api/trade_flow.php?action=preview` 已返回单据全量字段与 `can_claim / in_trade / is_party`，挂单大厅的角色判定（`$isMine / $inTrade / $isParty / $canClaim`）也已成型。本次变更是**纯编排工作**：新增一个公开页面 + 复用既有动作，不新增后端能力。

## What Changes

- **新增公开挂单详情页 `bct/order.php?id=N`**：任何人（含未登录）可访问，展示单号、方向、城市、单价/数量/总价、交易方式、挂单人、剩余有效期、状态
- **按角色渲染 CTA（一期为入口型）**：游客「登录后接单」、登录非本人「接单（买入）/接单（卖给TA）」、挂单人本人「管理我的挂单」、交易中参与方「继续交易」→ 跳 `user/dashboard.php#claims`
- **接单交互复用大厅模式**：点击 → preview 校验 → 确认弹窗 → POST `claim` → 跳个人中心进入交易流程；抢单失败改为顶部提示 + 页面自刷新（不再是 `alert`）
- **入口改造三处**：首页买入/卖出挂单条目、`orders.php` 行内城市/单号链接指向新详情页
- **隐私规则与大厅保持一致**：联系方式仅在交易中时对双方可见，未填写时引导站内信；「私信」收为挂单人名字旁的小图标链接
- **终态单不做 404**：已完成 / 已取消 / 已过期的单通过 URL 直达时显示对应状态与说明，分享出去的链接不会变成死链

## Capabilities

### New Capabilities
- `bct/trading/order-detail`: 公开挂单详情页——单据信息展示、按角色（游客/非参与方/挂单人/交易对手方）的 CTA 渲染、联系方式隐私规则、终态与失效态处理、接单入口与失败态反馈

### Modified Capabilities

（无——现有 specs 未覆盖公开详情页；本次不修改挂单大厅与接单流程的既有 requirement，只新增页面并复用既有动作）

## Impact

- **前端**：新增 `bct/order.php`（页面 + 样式沿用 `exchange-theme.css`）；改造 `bct/index.php`（两处列表条目链接）、`bct/orders.php`（行内链接）
- **后端**：无新增接口；复用 `bct/api/trade_flow.php` 的 GET `preview` 与 POST `claim`（含登录断言、CSRF、当事人校验）
- **数据库**：无变更
- **安全**：详情页为公开页，只暴露挂单的公开字段；`user/order_detail.php` 现状会查询 `email/phone`，新页面 MUST NOT 引用这些字段，也不新增任何私有字段展示
- **不做的事（一期）**：不把「确认已付款 / 确认已收款 / 放弃」内嵌进详情页（二期再评估）；不做部分成交；不动平台撮合与中介协调流程；不改联系方式可见性规则；不做评论/举报/收藏
