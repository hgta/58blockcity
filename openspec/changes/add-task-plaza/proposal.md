## Why

58 生态已有区块、BCT 交易、互访圈、商城、拍卖等子站，但缺少一个「人找人做事」的悬赏撮合场所。大量线下真实社交/经营动作——代互访、代打卡、代做市长——无处发布与成交：雇主（想省时间、想冲榜的人）找不到可靠的人，有闲力气的用户也无法用技能换取人气值或现金。新增独立子站「任务广场 task.58.tl」，补齐生态的 C2C 服务交易闭环，并与 城市/区块/互访圈 子站互相导流、互相沉淀信任。

## What Changes

- 新建独立子站 `task/`（线上 task.58.tl），完全沿用现有子站架构惯例（bid/club 模式）：共享 `includes/auth` 鉴权、共享 auth 登录模板、`shared/header` `shared/footer` 渲染、站点专属 `assets/`。
- 站点入口登记 4 处：`config/seo.php` subdomains、根 `index.php` 顶部导航 + eco-grid + 页脚、`shared/footer.php` cross-site-links、「探索生态」卡片、admin 菜单。
- 任务类别体系：**预设类别 + 开放描述**。类别后台可维护（发布时单选，任务标题与说明自由填写）。
- 雇主发布悬赏任务：标题 / 说明 / 类别 / 关联城市（可选）/ 关联对象（可选：区块、互访圈，用于 L1 导流）/ 赏金（人气值 或 现金）/ 名额 N（众包，N=1 即单人）/ 有效期 / 验收说明。
- 任务广场：浏览 + 按 类别 / 城市 / 赏金类型 筛选 + 排序（最新/赏金高）；任务卡与详情展示关联城市、关联对象并带「前往区块 / 互访圈」导流入口。
- 众包领取：任务名额内任意用户可领取一份（同任务每人限一份）；单份独立走「领取 → 交付 → 验收 → 结算」。
- 交付与核销：接单人提交**凭证（文字说明 + 截图）**；雇主验收 **通过 / 驳回**，驳回可补交再验收，超时未验收进入争议。
- 结算（**不托管**，验收通过后直接划转）：人气值任务经既有 `UserPopularity` 划转雇主 → 接单人（按任务城市）；现金任务按现有惯例走线下确认（站内仅状态记录，不进账本）。
- 争议与仲裁：雇主与接单人对驳回/跑单有异议可发起争议，admin 参照互访 `visits`/`nft_claim_appeals` 既有仲裁先例处理。
- 双向评价：任务单份完成结算后，雇主与接单人可互相评价，沉淀到双方信誉。
- 求职侧技能卡：用户可维护「可承接类别 + 简介 + 参考价」，在个人中心与任务站展示，雇主可按类别寻找承接人并发起联系。
- 数据与代码：新建 `init/migrate-task.sql`（任务/认领/类别/技能卡/评价/争议 表）与 `classes/Task*.php` 数据类；复用统一认证、CSRF、闪存、通知、头像等既有设施。
- 不做（本期范围外）：站内「每日打卡 / 市长」玩法本体、现金托管/冻结（escrow）、互访 `visits` 写入的深度打通（L2，留作 v2）、技能卡匹配推送。

## Capabilities

### New Capabilities

- `task/plaza`: 「任务广场」核心闭环能力——任务类别、发布悬赏、广场浏览筛选、城市/区块/互访圈关联与导流、众包领取、凭证交付、验收/驳回、人气值与现金结算、争议仲裁、双向评价、我的发布/我的承接。
- `task/skills`: 求职侧「技能卡」能力——用户发布与维护可承接的类别/简介/参考价，并在任务站内被雇主发现与联系。

### Modified Capabilities

（无。本 change 不改变既有 `bct/` 等 spec 行为；仅新增站点并登记入口。）

## Impact

- **新增目录/文件**：`task/` 子站（includes/auth、auth 代理、user/、admin/、assets）、`classes/Task.php` / `TaskClaim.php` / `TaskSkill.php` 等数据类、`init/migrate-task.sql`。
- **数据库**：新增任务相关表（tasks、task_claims、task_categories、task_skills、task_reviews、task_disputes，最终命名以 design 为准），不动既有业务表。
- **经济接入**：复用 `classes/UserPopularity.php`（按用户×城市人气值账本）做验收后划转；现金不产生站内资金变动。
- **入口登记**：`config/seo.php`（subdomains）、根 `index.php`（导航/eco-grid/页脚）、`shared/footer.php`（跨站引流）、admin 后台菜单配置。
- **依赖**：无新增第三方依赖、无支付网关接入。
- **风险**：不托管模式存在雇主「验收后不确认/跑单」风险，依赖实名与评价体系自然约束；发布与领取均需登录并校验用户有效状态。
